--- 2a. The two gates ----------------------------------------------------------
`platform.workspace_apps` (20 rows) and `platform.app_access` (49 rows) exist to
gate an app inside a shared workspace. Apps do not share workspaces any more, so
both are answering a question nobody asks.

  * remove `requireAppAccess` from `packages/platform-api`
  * remove `PLATFORM_ENFORCE_APP_ACCESS` from the code (the human removes the
    env var from Vercel)
  * remove the Apps panel from issues' workspace settings page — it is the UI
    for `workspace_apps`
  * DROP both tables, declared in the baseline first

**Check what else reads them before you drop.** Four times on this project the
thing that mattered was outside the app's own source: a Postgres trigger, a
shared factory, twelve FKs, and a shared route whose premise moved. `app_access`
in particular is read by `/api/meta`'s app registry — agent 4 §3 says the
registry is grant-derived, which is what makes the CLI's "no server known for
app" behaviour correct. **If you drop `app_access`, what does the registry
derive from?** That question is the real work of 2a, and I do not know the
answer.

3. PHASE 6 — CROSS-APP SEARCH, AS A FAN-OUT. OPTIONAL, AND READ THIS FIRST.
================================================================================
`bk search "acme" --all-apps` asks EVERY app's server with the same token and
merges, tagging each row with its app. Same for `bk activity`. No shared index,
no projection, no drift — **the CLI is the connector, which is this refactor's
whole thesis made literal.**

**Two constraints from earlier phases:**

  1. **Not every user can reach every app.** Agent 4: the registry is
     grant-derived, so a sales-only user's CLI has no `issues` entry. A fan-out
     must ask the apps THAT USER HAS, and say so — not fail, and not silently
     return one app's results as though they were all.
  2. **Each app now has its own active workspace** (agent 5's `ActiveWorkspaces`,
     keyed by app slug). A fan-out across apps is a fan-out across DIFFERENT
     workspaces. "Search my stuff" is well defined; "search this workspace
     across apps" is not, because the workspace is per app now. Decide what
     `--all-apps` means and say so plainly.

**It is optional. If constraint 2 makes it incoherent, say so and skip it** —
that is a better outcome than a flag whose meaning nobody can state. PLAN.md
already records the loss as deliberate.
