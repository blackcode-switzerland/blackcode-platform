1. WHAT THIS PHASE IS
================================================================================
The three-tier verb model (neutral / cross-app / app-owned) was built for shared
data. With identity as the only shared thing, the tiers collapse to two.

**The prize is not tidiness.** Today `bk trash purge` destroys things in
whichever app you were last homed on, and nothing in the command says which. An
agent cannot read back its own command and know what it hit. After you, every
command that touches an app's data names the app.


================================================================================
2. THE TARGET SHAPE
================================================================================
**Stays bare** — genuinely one thing everywhere, or about the binary itself:

    login · logout · whoami · token · profile · app · meta
    guide · changelog · skill · version

**Becomes app-owned** — `bk <app> <verb>`:

    workspace · member · invite · inbox · storage · trash · label · upload
    search · activity

`bk super-admin` is platform-wide administration over shared tables. **Leave it
bare**, and say in your reply whether you agree.

Already done by agent 4, do not redo: `search` and `link` are unmounted from
sales' HTTP surface. **`bk link` retires entirely** (PLAN.md §3).

3. THE THINGS THAT MAKE THIS PHASE HARD
================================================================================

--- 3a. Deprecations, in the same commit --------------------------------------
`cli/internal/commands/deprecations.go` — its own header states the rule: an
entry in the SAME commit as any rename or removal, keyed by the OLD spelling,
so a failed run becomes a recovered one.

**You are moving ten verbs.** That is the largest deprecation batch this repo
has ever taken, and it is the difference between an agent that retries correctly
and one that gives up. `bk workspace list` must not die with "unknown command" —
it must say where `workspace` went.

Watch a hint fire. Not the code path — the actual binary, actual old spelling,
actual stderr. `TestRemovedSpellingsStillCarryAHint` is CLAUDE.md finding #8: it
asserted a hand-written error string while the real one contained the whole
remaining argv, so the three most-used spellings fell through to the generic
hint. **Written by the session that wrote the standing rule, an hour after.**

--- 3b. The recovery hint is not available to everyone --------------------------
Agent 4 found this and it constrains what you can promise. When sales 404s a
verb it does not serve, the hint suggests `bk --app-server issues …`. **For a
user who only has sales, that recovery does not exist** — `/api/meta`'s registry
is grant-derived, so their CLI has no `issues` entry and `--app-server issues`
answers "no server known for app".

That is correct behaviour (an agent must not discover an app its user cannot
reach). It means a hint naming another app is actionable only for people who
have both. Take it into account in what your hints say.

--- 3c. The guards, which are the point ----------------------------------------
Every one of these must pass, and each must be watched failing:

  cli/internal/commands/routes_test.go     every leaf has a `routes` annotation
  cli/internal/commands/groups_test.go     a mistyped subcommand errors, never
                                           a silent help-and-exit-0
  cli/internal/commands/boundaries_test.go command packages don't import each other
  cli/internal/guide/guide_test.go         no hardcoded dynamic values; no
                                           cross-app references in a topic
  apps/*/lib/cli-parity.test.ts            every route reachable, every claim real
  packages/platform-testing/…/platform-route-coverage.test.ts

`cli-parity` is CLAUDE.md finding #10: it asserted on a UNION that could not go
empty, so deleting sales' entire guide topic tree left it 5/5 green. **When you
move a verb between apps you are changing exactly the set that test reads.**

`cd cli && make routes` after any `routes` annotation moves.

--- 3d. Guide topics ------------------------------------------------------------
`topics/platform/` shrinks to identity. Each app's topics grow. A topic under
`topics/<app>/` may not describe another app — `guide_test.go` enforces it, and
that test has been inert before (finding #9: a substring match over six
hand-written strings, which passed a topic containing an entire stale vocabulary).
